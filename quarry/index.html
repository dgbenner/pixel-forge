Who does what

Research agent

Gathers and scores

  • Searches docs, forums, other editors
  • Rates each idea on six signals
Judge agent

Picks, separately

  • Sees only the criteria, the inventory and the evidence
  • Never sees the researcher's reasoning
  • Picks 5–6, gives a reason for every reject
You

Set the rules, choose, build

  • Write the criteria the judge applies
  • Pick a feature and export its spec
  • Paste the spec into Claude Code to build it
What are the criteria?

A one-page file (criteria.md) that defines "better" for PixelForge. Its thesis: a lean editor built around the jobs people do when adjusting and compositing, not around Photoshop's darkroom-era feature list.

  • Job first: name the job, not the tool
  • One good way per job
  • Expert control in plain language
  • Non-destructive by default
  • Customizable (presets, defaults)
  • Composite-first
  • Every feature works for people and for the editing agent
How do I run it again?

In the Claude Code panel in VS Code, with the pixel-forge folder open, type /feature-quarry. It saves a new dated report and adds the run to this page. Earlier runs stay available in the run picker at the top and in the Runs tab.

What it can't do

It can't measure real usage. Adobe doesn't publish it. The ratings are proxies from public writing: documentation depth, forum threads, tutorial supply.

It checks whether a feature works and fits the criteria. Whether it's worth having is your call.
